# CLAUDE.md — digitalcrew-auth

## The repository
- Package `@digitalcrew/auth`: shared Digital Crew authentication (Better Auth + Drizzle ORM + Postgres), multi-tenant through organizations (Better Auth `organization` plugin).
- Consumed by other applications as a Git dependency (`prepare` runs `npm run build` on install); it also ships the `digitalcrew-auth migrate` binary, which applies `drizzle/` to the client application's database.
- Strict TypeScript, ESM (`"type": "module"`, `module: NodeNext`): relative imports keep the `.js` extension (`./env.js`).
- Package manager: npm (`package-lock.json`). Node `>=20` (`engines` field; no `.nvmrc`); CI uses Node 24.

## Commands (package.json)
- Install: `npm ci` (triggers `prepare` → build). The `overrides` block in `package.json` aligns the `drizzle-kit` and `drizzle-orm` peers of `better-auth`, so `--legacy-peer-deps` is no longer needed. Do not regenerate `package-lock.json` unless asked.
- Build: `npm run build` (`tsc`, output in `dist/`, not versioned).
- Type check without writing `dist/`: `npx tsc --noEmit` (no `typecheck` script; passes today).
- `npm run auth:generate`: regenerates `src/schema/auth.ts` from `src/auth.cli.ts` (through `npx auth@latest`, needs the network).
- `npm run db:generate`: generates a new Drizzle migration in `drizzle/`.
- `npm run db:migrate` / `npm run db:studio`: touch a real database (`DIGITALCREW_AUTH_DATABASE_URL`). Do not run them without human approval.
- Tests: `npm test` (build, then `node --test test/*.test.mjs`, Node's built-in runner).
- CI: `.github/workflows/ci.yml` runs `npm ci`, `npx tsc --noEmit`, `npm run build`, the tests and `npm audit --omit=dev --audit-level=critical`.
- Missing: no `dev`, `lint` or `typecheck` script, no ESLint/Prettier config.

## Structure
- `src/index.ts`: public exports (`.` entry point); `src/http.ts`: `routeHandlers` adapter (`./http` export).
- `src/auth.ts`: `createAuth(env)` / `getAuth()` (cookies, optional Google, plugins).
- `src/env.ts`: Zod schema of the environment variables (`loadAuthEnv`).
- `src/tenant.ts`: organization plugin options (`digitalcrewOrganization`).
- `src/db.ts`: Drizzle client; `src/client.ts`: browser client.
- `src/schema/auth.ts`: Drizzle schema generated by `auth:generate`.
- `src/auth.cli.ts`: minimal config used only by the Better Auth generator.
- `src/cli/migrate.ts`: `digitalcrew-auth` binary.
- `drizzle/`: SQL migrations + `meta/` (drizzle-kit journal and snapshots).

## Rules
- Never edit an existing migration in `drizzle/` or `drizzle/meta/` by hand: they ship in the package and are already applied in client applications. Every change goes through a new migration (`npm run db:generate`), additive (expand/contract: add first, remove later).
- Adding or removing a Better Auth plugin: copy the same list into `src/auth.cli.ts` (the file's comment requires it), then `auth:generate`, then `db:generate`. Do not edit `src/schema/auth.ts` by hand.
- New environment variable: add it to the schema in `src/env.ts` and to the README table; in `.env.example`, the name with an empty or dummy value (today `NODE_ENV` is not there, and the optional `AUTH_*` limits are only there as comments).
- Secrets only as dummy values in `.env.example`; never read or commit `.env` (ignored by `.gitignore`). No hard-coded production host.
- The public API (`src/index.ts`, `exports` in package.json) is used by other repositories: no breaking change without saying so in the PR.
- `npm run build` must pass: a `tsc` error breaks installation in client applications.
- Tests live in `test/*.test.mjs` and run against the built `dist/`: add or update a test with each behaviour change.

## Git flow
- Branch `claude/<card-key>-<keyword>`, from `main`.
- PR to `main` (the default branch) with human review.
- Never push to `main` or `develop`, never merge, never force-push.
- Before pushing: `npx tsc --noEmit` and `npm test` (there is no lint).
